# AI Resume Refiner

Tailors an existing DOCX resume to a job description. The AI suggests changes, the user approves or rejects each one, and only approved changes are applied to the original document.

## Requirements

- Python 3.11 or newer
- Node.js 20 or newer

## Run the backend

```bash
cd backend
python -m venv .venv

# Activate the virtual environment
# Windows (PowerShell):  .venv\Scripts\Activate.ps1
# Mac / Linux:           source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env          # Windows: copy .env.example .env
uvicorn app.main:app --reload
```

Check it: open http://localhost:8000/api/health and you should see `{"status":"ok",...}`.
Interactive API docs (generated by FastAPI): http://localhost:8000/docs

Run the tests (with the virtual environment active):

```bash
pytest
```

### AI key (Milestone 3)

1. Create a key at https://aistudio.google.com ("Get API key").
2. Put it in `backend/.env` as `GEMINI_API_KEY=...` (copied from `.env.example`). Never commit `.env`.
3. For the live site: Render > resume-refiner > Environment > add `GEMINI_API_KEY`.

Without a key, the app still runs; the analyse button explains that AI isn't set up.
Tests never call the real AI: they replace it with a stand-in.

### Preview (Milestone 6)

The before/after preview and page count need LibreOffice and poppler-utils on the server.
The Docker image installs them. On your own laptop they're optional: without them the
app still works and says the preview isn't available, and the rendering tests are skipped.
(Windows: install LibreOffice and poppler, and make sure `soffice`, `pdfinfo` and
`pdftoppm` are on your PATH, if you want the preview locally.)

## Privacy and security

- **Uploads:** `.docx` only, 5 MB max, must be a real Word file, no macros, at most 5,000 paragraphs and 20 MB unzipped. Any request body over the limit is refused before it's saved.
- **Storage:** each upload lives in its own temp folder as `original.docx` and is never modified. Everything is deleted when the user clicks Remove, or by a background job 60 minutes after the last action.
- **AI:** nothing is sent until the user ticks a consent box that names the provider and tier. The top contact block and Personal Details, Declaration, Contact and References sections are never sent. The person's name, emails, phone and other long numbers, links, PAN and passport numbers, and date-of-birth lines are masked elsewhere. Masking is pattern-based and the notice says it can miss unusual formats.
- **Limits:** per network, per session and per day caps on AI analyses protect the free AI quota.
- **Logs:** session IDs, counts and error types only. Never file names or resume text. Unexpected errors show a generic message.
- **Browser:** security headers (content security policy, no framing, no sniffing, no referrer). The `/docs` API page is off in production.
- **Keys:** only in environment variables (`backend/.env` locally, Render's Environment tab live).

## How the brief's rules are enforced

The AI is *told* the rules (`analyzer.py`), but the code also *checks* them, because being told isn't proof.

| Rule in the brief | Where it's enforced | Tested in |
|---|---|---|
| Never invent skills, projects, achievements | `suggestion_checks.py` drops proposals that add numbers, tool-like terms, or job-description words the resume never uses | `test_suggestion_checks.py`, `test_hardening.py` (7) |
| Don't make content sound more impressive | `suggestion_checks.py` drops proposals that add words like "led", "spearheaded", "owned" | `test_hardening.py` (7) |
| Smallest useful change | "shorten" must be shorter; "emphasise" must only reorder; edits touch only the changed runs | `test_suggestion_checks.py`, `test_docx_editor.py` |
| Never remove content without approval | Removal happens only on an explicit "Remove line" click; undecided = unchanged | `test_decisions.py` |
| Apply only approved changes | Decisions are versioned; files and previews made from older decisions are never served | `test_decisions.py`, `test_hardening.py` (1, 2, 13) |
| Don't change design or formatting | Run-level editing; validator compares untouched paragraphs byte-for-byte | `test_docx_editor.py` |
| Resume already fits: recommend nothing | `no_changes_needed` shown as "No changes are recommended" | `test_analyze.py` |
| Explain each change | Every suggestion carries a reason; dropped ones show why | `test_analyze.py` |
| Ask instead of guessing | Missing requirements become questions, never additions | `test_analyze.py` |
| Only add what the user confirms | Answer cards may only add words from the user's own answer (or already in the resume); no new numbers or seniority words; No answers are never sent | `test_answers.py` |
| One change per line | Accepting a second change for a line that already has one is refused; the user undoes one or edits to combine | `test_answers.py` |
| Relevance is a recommendation | "Consider removing" wording; the user can always keep | UI |
| Keep the original; validate the result | Original never written; validator must pass before download | `test_docx_editor.py`, `test_decisions.py` |

Page counts in the preview are estimates (LibreOffice, not Word), and the app says so.

## Deployment checklist

1. Push to `main`. GitHub runs the tests (see the green tick), and Render builds the Docker image.
2. In Render > Environment, set `GEMINI_API_KEY`. The other variables have defaults in `render.yaml` and `config.py`.
3. After deploy, `/api/health` should show the new version, `"configured": true` and `"preview_available": true`.
4. On a paid AI key, set `GEMINI_TIER=paid` so the privacy notice stays accurate, and consider raising the analysis limits.

## How the pieces connect

```
Browser  ->  Vite dev server (5173)  --/api/*-->  FastAPI (8000)
```

The Vite dev server forwards every `/api/...` request to FastAPI (see `frontend/vite.config.js`), so the browser only talks to one address and no CORS setup is needed.

**Slow AI steps run as background jobs.** `POST .../analyze` and `POST .../answers` do their quick checks, then return `202` with a `job_id` straight away. The page checks `GET .../jobs/{job_id}` every 2 seconds until the job is `done` or `failed`. A check that fails because the connection dropped (a phone locking or switching networks) is simply retried; the result waits on the server (`app/jobs.py`).

**Backup model.** If the main model (`GEMINI_MODEL`) is busy or over its free limit, the next attempt goes to `GEMINI_FALLBACK_MODEL` (default `gemini-3.5-flash-lite`), which Google runs separately. The privacy notice names both models. Set `GEMINI_FALLBACK_MODEL=` (empty) to switch it off. Render logs show which model answered: `AI answered in 12.3s (attempt 2, gemini-3.5-flash-lite)`.

## Production and deployment

In production there is no Vite server. The `Dockerfile` builds the React app into static files and FastAPI serves them alongside the API, so the whole app is **one service at one URL**:

```
Browser  ->  FastAPI  (/api/* = API, everything else = built React files)
```

Try production mode locally without Docker:

```bash
cd frontend && npm run build && cd ../backend
STATIC_DIR=../frontend/dist uvicorn app.main:app --port 9000
# open http://localhost:9000
```

Deploy on Render (free plan): push this repo to GitHub, then in Render choose **New > Blueprint**, pick the repo, and confirm. Render reads `render.yaml`, builds the `Dockerfile`, and redeploys on every push to `main`. The free plan sleeps when idle, so the first visit after a while takes extra time to wake up.

## Project layout

```
backend/
  app/main.py          FastAPI app and routes
  app/config.py        settings from environment variables
  app/validation.py    upload checks (type, size, real DOCX, no macros)
  app/storage.py       temp session folders and automatic cleanup
  app/docx_reader.py   paragraphs in reading order, with IDs and sections
  app/schemas.py       shape of the AI's answer (also sent to Gemini as its schema)
  app/analyzer.py      prompt, privacy masking, the Gemini call (only file that knows the provider)
  app/suggestion_checks.py  safety net that drops invented or unsafe suggestions
  app/decisions.py     accept / reject / edit rules and the summary of what will change
  app/docx_editor.py   writes approved changes into a copy, run by run, keeping formatting
  app/validator.py     reopens both files and checks only approved text changed
  app/renderer.py      LibreOffice -> PDF -> page images and page count (one at a time)
  app/page_fit.py      page-limit check and the options offered to the user
  app/limits.py        request size limit and rate limits
  app/jobs.py          background jobs for the slow AI steps
  app/answers.py       turns confirmed answers into suggestions, with answer-only checks
  samples/             fake sample resume and the script that builds it
  tests/               pytest tests
frontend/
  src/api.js                     all calls to the backend
  src/App.jsx                    main screen, holds the current state
  src/components/UploadStep.jsx  upload box
  src/components/ResumeOutline.jsx  "what we read" view
  src/components/JobDescriptionStep.jsx  job description box and consent
  src/components/AnalysisView.jsx  requirements, suggestions, questions
  src/components/SuggestionCard.jsx  one suggestion with Accept / Edit / Reject
  src/components/DecisionSummary.jsx  counts and the list of what will be applied
  src/components/PreviewPanel.jsx  before/after pages, page limit and options
  src/components/QuestionsPanel.jsx  answer the AI's questions in your own words
  src/diff.js                    word-level highlighting of changes
  vite.config.js                 dev server and /api proxy
```
